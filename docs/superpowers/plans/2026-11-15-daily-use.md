# Daily-use file manager implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans task by task. The user authorized autonomous implementation; root integrates and reviews, Opus 5.5 High reviews consequential decisions.

**Goal:** Make routine file browsing, organizing, archiving and Explorer handoff usable without switching applications unnecessarily.

**Architecture:** Retain Rust/GPUI and bounded asynchronous services. Separate virtual archive locations from filesystem operations; isolate Windows Shell integration behind explicit adapters.

**Tech Stack:** Rust, GPUI, Windows Shell COM, ZIP/7z libraries selected after source/API inspection.

**Spec:** `docs/superpowers/specs/2026-11-15-daily-use-design.md`

## Global constraints

- No scans, Shell calls or compression on the UI thread; finite workers, queues and memory.
- Preserve existing data and unrelated changes; no silent overwrite or ambiguous Explorer close.
- Conventional feature commits with bodies and validation; no push.

## Review focus

- Watcher updates while a filename input is focused must not target a different file.
- Archive paths, symlinks/reparse points, corruption and cancellation must not escape output or publish partial success.
- Explorer tabs sharing one HWND must not cause an entire unrelated window to close.
- Progress/cancel transitions must accurately report partially completed work.
- External selection requests must survive asynchronous folder loading and Unicode paths.
