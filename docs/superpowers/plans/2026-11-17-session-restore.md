# Session Restore Implementation Plan

ユーザー承認：推奨順で実装し、Opus 5.5 mediumでレビューする。タブ復元は設定でオン／オフ、ウィンドウサイズは設定不要。

## 設計

タブ復元は既定オン。各ウィンドウの場所と選択タブを再起動時に復元する。外部の明示パス・Shell引き継ぎ起動ではその要求を優先する。復元オフではホーム1タブで開き、保存時にもタブのパスを除外する。ウィンドウ位置・サイズ・最大化は常に保存し、現在の画面へ収める。

UIは有界のメモリ上スナップショットのみを更新し、保存・読込はUI起動前／ワーカーで実施する。最大8ウィンドウ・各32タブ、ファイル512KiB、パス4096バイト。書庫タブは書庫の親フォルダーへ復帰する。存在確認で起動をブロックせず、消失先は既存の読込エラーとして扱う。選択・検索文字・戻る履歴・フォルダー別表示設定は対象外。

通常のウィンドウcloseとアプリquitで保存する。途中で閉じたウィンドウは次回復元から除き、最後の1窓を閉じたときはその構成を残す。クラッシュ復元／複数プロセス間の統合は対象外（最後に保存したプロセスが優先）。不正・将来版のsessionは保持して上書きを止め、ホームへフォールバックする。

## レビュー対応

- 画面UUIDと画面内相対座標を保存し、復元先display_idを明示する。利用可能領域へ配置を制限する。
- 外部パス／Shell起動のプロセスは通常セッションの保存を行わない。
- 未完了の変更がある設定だけ終了時flushする。オフにした際は通常セッションのパス除去を即時キューイングする。不正ファイル保持による保存停止は維持する。
- 設定とセッションのエラーを両方表示し、エラー行を含めたスクロール位置を計算する。
- 初回のGPUI終了テストは、実I/O完了より仮想タイムアウトが先行した。テストだけtick猶予を設定した。実アプリの200ms猶予は維持。
- 既存スクロール試験が一度失敗したが、コード変更なしの次回全実行では成功。最終全実行323件成功・既存2件ignore。
- Windows実行ファイルの実機起動はウイルス対策機能により拒否された。保護設定は変更せず、実機検証は未完了とする。
- Opus 5.5 mediumの再レビューは重大指摘なし。macOSのメニューバー／Dock、Windowsの上・左タスクバーによる座標差は実機未確認の制約として記録した。
- リリースビルド成功（既存警告2件）、fmt・diff・文書リンク確認成功。
