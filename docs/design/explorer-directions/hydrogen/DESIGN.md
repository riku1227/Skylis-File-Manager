# Explorer デザイン方向性 3案 — 設計メモ（hydrogen）

Windows 優先・将来 macOS 対応の **Rust GPUI Fast** 製デスクトップファイルエクスプローラーに向けた、構造・奥行き・余白・操作系を刷新した **3つの独立したデザイン方向性**。

- すべて単一 HTML（CSS / JS / SVG 埋め込み・外部ネットワーク通信なし）
- 日本語 UI、比較検証のため [explorer-concept](../../explorer-concept/concept.html) と同一の架空サンプルデータセットを共用
- ファイル・フォルダー・ドライブのカラーアイコンは OS ネイティブアイコン（Windows `SHGetFileInfoW` / macOS `NSWorkspace`）の**仮素材（SVG 代用）**、操作アイコンは統一された単色線画 SVG（`currentColor`）

## 案1: Airy Canvas（エアリー・キャンバス）
ファイル: [`concept-1.html`](./concept-1.html) / スクリーンショット: [`screenshots/concept-1.png`](./screenshots/concept-1.png)

### 狙いと構造
- **「重たいシステム UI 感」からの脱却**：従来の全面無彩色グレーの帯と 1px 格子線をやめ、淡く光を感じる外周キャンバス（`--bg-canvas`）の上に、白いコンテンツシートと半透明カプセル群を浮かせる構成。
- **統合オムニバー**：戻る/進む/上へ・更新カプセル、パンくずリスト＋ライブ検索をまとめた中央カプセル（`.omni-pill`）、表示切替・外観切替カプセルを 1 行に整理し、ツールバーの圧迫感をなくした。
- **軽やかな一覧と余白**：行高 34px（コンパクト 27px）、左右インセット付きの丸角行、種類欄のソフトピルバッジにより、情報密度を保ちながら視線の呼吸を確保。

### 主なトークン（ライト / ダーク）
- `--bg-canvas`: `#f2f6fb` / `#10141c`
- `--bg-sheet`: `#ffffff` / `#161b25`
- `--bg-glass`: `rgba(255,255,255,0.80)` / `rgba(25,31,44,0.78)`
- `--bg-selected`: `#e7f0ff` / `#1b3256`
- `--accent`: `#0f6fff` / `#5ba0ff`

### GPUI 実装上の注意点と代替案
- ヘッダーの `backdrop-filter: blur(16px)` は、GPUI 単体ではリアルタイム背景ブラー負荷が高いため、**OS 側のウィンドウ透過（Windows Mica / macOS NSVisualEffectView）を背面に敷くか、不透明度 92% 前後の単色ティント＋1px 上端ハイライト線で代替**するのが現実的。
- キャンバスの微弱なラジアルグローは、実アプリではウィンドウ全体の単色背景（または 1 回描画の軽量シェーダ）に置き換えてスクロール時の再描画コストをゼロにする。

## 案2: Tactile Studio（タクタイル・スタジオ）
ファイル: [`concept-2.html`](./concept-2.html) / スクリーンショット: [`screenshots/concept-2.png`](./screenshots/concept-2.png) ・ [`screenshots/concept-2-columns.png`](./screenshots/concept-2-columns.png)

### 狙いと大胆な構造変更
- **上段共通ツールバーと右サイドペインを廃止**：
  1. 左端に **52px アイコンレール** を常設し、よく使う場所への即時ジャンプとドロワー開閉・隠しファイル・テーマ切替を集約。
  2. メイン上部に **タイトル起点のステージヘッダー**（現在フォルダー名を 20px 太字で提示し、直上にパンくず・件数チップ、右側に検索と 3 視点切替）を配置。
  3. 右インスペクタを廃し、**下部水平インスペクタデッキ（148px）** へ再配置。これにより長い日本語ファイル名や更新日時・種類・サイズ列の横幅を一切削らずに詳細・テキストプレビュー・操作ボタンを常時表示できる。
- **3 視点切替（詳細 / カラム / アイコン）**：`カラム` ビューでは階層を横並びのスクロール列（Miller Columns 風）で辿れる。
- **温かみのあるスタジオ質感**：無彩色グレーを避け、ストーン／ウォームペーパー基調に深みのあるティール（`#0c7a69`）を差し色に採用。

### 主なトークン（ライト / ダーク）
- `--bg-rail`: `#eeece5` / `#121416`
- `--bg-drawer`: `#f6f4ee` / `#181a1d`
- `--bg-stage`: `#fcfbf8` / `#1d2024`
- `--bg-deck`: `#f5f3ec` / `#17191c`
- `--bg-selected`: `#e0efe9` / `#163b36`
- `--accent`: `#0c7a69` / `#36c4aa`

### GPUI 実装上の注意点と代替案
- **GPUI 親和性が最も高い案**：ブラーや多段グラデーションに依存せず、ソリッド塗り・1px 罫線・角丸・1 段の軽い影だけで質感を出しているため、`div()` と `uniform_list` でそのまま高速再現可能。
- 下部デッキの高さ（148px）は将来的にドラッグリサイズ可能なスプリッタへ拡張しやすい。カラムビューは複数 `uniform_list` の水平コンテナとして実装でき、高速仮想スクロールと相性が良い。

## 案3: Translucent Horizon（トランスルーセント・ホライゾン）
ファイル: [`concept-3.html`](./concept-3.html) / スクリーンショット: [`screenshots/concept-3.png`](./screenshots/concept-3.png)

### 狙いと大胆な構造変更
- **左サイドバーを完全に廃止**：固定の縦帯（200px 級）を無くし、コマンドバー直下の **水平場所＆ドライブリボン（38px）** に「よく使う場所」と「C:/D: 空き容量ミニゲージ」を統合。ウィンドウ全幅をファイル一覧と詳細ペインに開放した。
- **浮遊グラスレイヤー（Liquid Glass 的表現の探求）**：
  - 上部浮遊グラスコマンドバー（カプセル型）
  - 水平リボンと半透明ファイルシート
  - 下部中央の **浮遊グラスステータスカプセル**（`position: absolute; bottom: 18px` でファイル一覧の下端余白に浮かぶ）
- **可読性との両立**：背景を柔らかなイリデッセント・グラデーションにしつつ、文字が載る一覧シートと詳細ペインは透過率を抑え（`0.78`〜`0.88`）、選択行は半透明グラデーション＋上端スペキュラハイライトでコントラストを確保。

### 主なトークン（ライト / ダーク）
- `--bg-ambient`: `linear-gradient(135deg, #e9f0fd, #f1ecfc, #e6f5f3)` / `linear-gradient(135deg, #0b0e19, #141024, #0c171c)`
- `--bg-glass`: `rgba(255,255,255,0.72)` / `rgba(24,27,42,0.72)`
- `--bg-glass-sheet`: `rgba(255,255,255,0.78)` / `rgba(20,23,36,0.78)`
- `--accent`: `#5248e5` / `#8589ff`

### GPUI 実装上の注意点と代替案（重要）
- **OS API・シェーダ依存要素の代替**：HTML モックでは CSS `backdrop-filter: blur(22px) saturate(160%)` と透過背景でガラス感を表現しているが、GPUI では要素単位のリアルタイム背景ブラー（特に高速スクロールする `uniform_list` 背後での浮遊カプセルブラー）は GPU 帯域負荷が高くなりやすい。
- **推奨代替実装**：
  1. ウィンドウ全体の背面には OS ネイティブ素材（Windows 11 `Mica Alt` / `Acrylic`、macOS `NSVisualEffectView` / Liquid Glass 相当 API）を適用し、アプリ内レイヤーは **半透明単色ティント（例: `rgba(255,255,255,0.82)`）＋上端 1px スペキュラボーダー** で奥行きを出す。
  2. 下部浮遊ステータスカプセル後ろのスクロール領域は、ブラー無しでも可読性が落ちないようカプセル側の不透明度を `0.90` 以上に設定する。
- **性能検証事項**：120Hz 環境で `uniform_list` 高速スクロール時のフレーム時間（8.3ms 以内）と、Windows Acrylic 有効時のリサイズ追従性を実機ベンチマークで計測すること。

## 検証結果

ヘッドレス Chrome（CDP 経由・HTTP サーバー不要）にて 3 案すべてを描画・操作検証し、スクリーンショットを [`screenshots/`](./screenshots/) に保存した。

- **画面サイズ・レスポンシブ**（`1280×800` / `1100×700`・ライト / ダーク）：
  - 3 案すべてで横スクロールなし（`scrollWidth === innerWidth`）、縦はみ出しなし（`scrollHeight === innerHeight`）、ヘッダー／リボン／レールのボタン見切れ `0` 件。
  - 一覧行の実効幅（`1280×800` 詳細表示時）：案1 `718px` / 案2 `1008px` / 案3 `914px`（構造変更による横幅確保の効果を確認）。
