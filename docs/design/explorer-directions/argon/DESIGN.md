# デスクトップファイルエクスプローラー 新デザイン3案（Argon Directions）

本ドキュメントは、Rust `gpui` (`gpui-ce` / GPUI Fast) ベースのデスクトップファイルエクスプローラー向けに制作した独立3案（[concept-1.html](./concept-1.html)、[concept-2.html](./concept-2.html)、[concept-3.html](./concept-3.html)）の設計意図、構造・視覚的差異、デザイントークン、および GPUI 実装時の代替手段・性能検証事項をまとめた仕様書です。

---

## 1. 前回評価の独自解釈と刷新方針

### 課題の構造的要因
ユーザーからの評価「*macってあまりグレーを使ってるイメージがない。パッとしない。もっと今風。これは一個前のトレンドのシステムUIに見える。もっと大胆に変えて良い*」に対し、単に背景色の彩度を上げる・選択色を変えるだけでは解決しないと考え、以下の4点を根本原因として再定義しました。

1. **「1px 境界線で区切られたエッジ・トゥ・エッジの灰色の箱」構造**
   - 従来のシステムUI（旧世代の Finder や Windows Explorer、典型的な Electron 製管理画面）は、画面全体を上下左右に 1px ボーダーで直線分割し、各ペインの識別に「異なる明度の無彩色グレー（`#F3F3F3`, `#EBEBEB` 等）」を割り当てていました。これが画面全体を「曇り空のようなグレーの塊」に見せる最大の原因です。
2. **「面の奥行き（空間レイヤー）」と「スペキュラ（光の反射・透過）」の欠如**
   - Apple の 2025 年の新デザイン言語（Liquid Glass）をはじめとする現代のシステム UI は、コンテンツ（ファイルキャンバス）を最優先の純粋な面として広げ、ナビゲーションやツールバーを**同心円状の角丸（Concentric Rounded Corners）を持つ半透明フローティングレイヤー**として浮かせることで、グレーの塗り分けに頼らずに空間階層を作っています。
3. **「フォルダ階層移動」と「ファイル精査」の同一視**
   - すべての項目を同じ高さ・同じ密度のフラットな表に詰め込むため、視覚的リズムが単調になり、日常ツールとしての心地よさや情報探索の俊敏性が損なわれていました。
4. **タイポグラフィと選択表現の平板さ**
   - 12px〜13px の均一な文字サイズと、ベタ塗りの矩形選択行が「事務的なスプレッドシート感」を強めていました。

## 2. 各案の詳細設計とトークン

### 案1: Prism Canopy（プリズム・キャノピー）— 明るく軽やかな空間レイヤーUI

- **ファイル**: [concept-1.html](./concept-1.html)
- **スクリーンショット**: [concept-1-light.png](./screenshots/concept-1-light.png) / [concept-1-dark.png](./screenshots/concept-1-dark.png)

#### 狙いと特徴
- **脱・灰色システムUI**: ウィンドウのベースに極めて淡いスカイブルー〜ラベンダー〜ウォームポーセリンのアンビエントな光彩を敷き、その上に**純白（`#FFFFFF`）のファイルステージ**と**半透明ガラスのナビゲーション／キャノピーバー**を浮かせた、明るく澄んだ常用エクスプローラー。

- **インライン・クイックフィルタピル**: ファイルステージ上部に「すべて / フォルダ / ドキュメント / コード・データ / メディア」の即時絞り込みピルを配置し、検索語入力と組み合わせて1クリックで目的のファイルを抽出可能。

### 案2: Kinetic Horizon（キネティック・ホライズン）— 大胆な構造刷新・高速操作UI

- **ファイル**: [concept-2.html](./concept-2.html)
- **スクリーンショット**: [concept-2-light.png](./screenshots/concept-2-light.png) / [concept-2-dark.png](./screenshots/concept-2-dark.png)

#### 狙いと特徴
- **左サイドバーと上部ツールバーの廃止（構造刷新）**: 常時 220px 以上を占有していた左ツリーペインを廃止し、上部の**「ホライズン・プレイス＆ストレージリボン」**に集約。これにより、1280px 幅でも 1100px 幅でも**画面横幅 100% をファイルテーブルに開放**します。
- **サブフォルダ・ファセットシェルフ（Folder Shelf）**: 「フォルダを辿る操作」と「ファイルを精査する操作」を視覚的に分離。現在のディレクトリ直下のサブフォルダを上部の横並びカード棚として独立表示（トグルで折りたたみ可能）し、下の詳細テーブルには純粋にファイル群（または全項目）を整然と並べます。
- **視覚的スキャナビリティを極めた詳細リスト**:
  - **拡張子モノスペースバッジ**: `.xlsx`, `.pdf`, `.rs`, `.png` などを瞬時に識別できるピル型モノスペースバッジ列。
  - **対数スケール相対サイズバー**: ファイルサイズ数値の横に、フォルダ内最大ファイルに対する対数比のミニプログレスバーを表示し、大容量ファイルを一目で把握可能。
- **下部フローティング・コマンドドック（Command Dock）**: 戻る/進む、検索フィルタ、表示モード切替、新規作成・削除などの主要アクションを画面下部の高コントラスト・フローティングドックに集約。

## 3. アイコン設計と仮素材に関する明示

1. **ファイル・フォルダ・ドライブ等のオブジェクトアイコン（OSカラーアイコン尊重）**
   - 本HTML試作では外部ネットワーク通信を行わず単一HTMLで完結させるため、OSネイティブのカラーアイコンおよびサムネイルを模した**リッチなカラーグラデーションSVG（仮素材）**をインライン埋め込みしています。
   - この旨は本体UIのノイズにならないよう、各案右上の「設計ノート」モーダルおよび本ドキュメントにのみ記載しています。
   - **実機（Rust GPUI）での実装方針**:
     - **Windows**: `SHGetFileInfoW` / `IShellItemImageFactory::GetImage` によりシステムアイコンおよび実ファイルサムネイルを非同期取得し、GPUI のテクスチャキャッシュ（LRU）へ格納して描画します。
     - **macOS（将来対応）**: `NSWorkspace.shared.icon(forFile:)` および `QLThumbnailGenerator` から取得した `NSImage` を RGBA バッファ経由で GPUI `RenderImage` に変換します。
2. **ツールバー・ナビゲーション等の操作アイコン（統一SVG）**
   - 戻る、進む、上へ、検索、表示切替、ペイン切替、新規フォルダ、削除などの操作系アイコンは、`stroke-width: 1.75`〜`1.8`、`stroke-linecap: round`、`stroke-linejoin: round` で統一した単色ベクターSVGを使用し、`currentColor` でテーマ色・状態色に追従させています。

## 4. GPUI 実装代替案と性能検証事項（重要）

本試作では現代的な質感（半透明ガラス、同心円角丸、スペキュラ境界、局所グラデーション、サイズバー等）を積極的に取り入れていますが、**「日常の高速なファイル操作（60〜120fps のリストスクロール、数万件ディレクトリの即時展開）を決して犠牲にしない」**ことが大前提です。GPUI でそのまま再現保証するのではなく、以下の実装代替と性能検証を行います。

### 4.1 半透明ガラス（Liquid Glass 調レイヤー）と背景ぼかし
- **HTML試作での表現**: `backdrop-filter: blur(20px) saturate(180%)` ＋ 半透明背景色 ＋ 上縁 `1px` の高輝度スペキュラボーダー。
- **GPUI での実装代替**:
  - GPUI 内部で毎フレーム動的ガウシアンブラー（背景キャプチャ＋シェーダブラー）を複数のフローティング要素にかけると、スクロール時の GPU フィルレート負荷が増大します。
  - **代替手段 A（推奨・高速）**: ウィンドウ最背面にのみ OS ネイティブのウィンドウマテリアル（Windows 11: `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_MAINWINDOW` / `DWMSBT_TABBEDWINDOW`、macOS: `NSVisualEffectView` の `.underWindowBackground`）を適用し、アプリ内のフローティングパネル（キャノピーバー、ナビドック等）は **「高不透明度（88%〜94%）のティント付き `hsla()` 塗り ＋ 1px スペキュラ内側ボーダー ＋ 1段のソフト `BoxShadow`」** で疑似ガラス質感を表現します。
  - **代替手段 B**: フローティングドックの背後にリストが潜り込まないレイアウト（案1・案3のように各アイランドが分離している構造）では、動的ブラーを使わずともアンビエント背景色の微細なティント差とスペキュラ枠線だけで同等以上の透明感・奥行きが得られます。
- **性能検証事項**:
  - 10,000 ファイルの `uniform_list` を高速スクロールした際、フレームタイムが `8.3ms`（120Hz）または `16.6ms`（60Hz）を超えないこと。

### 4.2 局所的グラデーションと選択行カプセル
- **HTML試作での表現**: 選択行やアンビエント背景に `linear-gradient` / `radial-gradient` を使用。
- **GPUI での実装代替**:
  - GPUI の `linear_gradient` プリミティブが使用可能な箇所（ヘッダーピルや選択行背景）は 2 ストップの軽量グラデーションを使用。
  - もし `uniform_list` 内の大量の行でグラデーションシェーダがバッチングを阻害する場合は、**「淡いティント単色背景（例: `hsla(220, 85%, 55%, 0.10)`）＋ 左端または全周の 1px アクセントボーダー（`hsla(220, 85%, 55%, 0.35)`）」**にフォールバックします。これでもカプセル型角丸（`rounded(px(10.0))`）を維持すれば従来のような「ベタ塗り矩形」にはなりません。

### 4.3 案2の「対数スケール相対サイズバー」と拡張子バッジ
- **HTML試作での表現**: 各ファイル行に拡張子ピルと相対サイズバーを描画。
- **GPUI での実装代替と性能検証**:
  - フォルダ読み込み完了時にディレクトリ内の `max_file_size`（または `f64::ln(max_size)`）を 1 回だけ事前計算し、各アイテムの正規化比率 `ratio: f32`（`0.0..=1.0`）をキャッシュします。
  - 描画時は `uniform_list` の可視行（約 20〜30 行）に対してのみ、固定幅 `div().w(px(48.0)).h(px(4.0))` の中に `div().w(relative(ratio))` を 1 つ配置するだけなので、レイアウト・描画コストは実質ゼロです。

### 4.4 案2の「下部コマンドドック」・オーバーレイドロワー
- **HTML試作での表現**: `position: fixed` / `position: absolute` によるフローティング配置。
- **GPUI での実装代替**:
  - GPUI の `deferred(anchored().anchor(Corner::BottomCenter)...)` またはルート `div().relative()` 内の `.absolute().bottom(px(16.0))` レイヤーとして配置します。
  - ドック背後のファイルリスト最終行が隠れないよう、`uniform_list` の下部パディング（または末尾スペーサー要素）に `72px` を確保します。

## 5. ブラウザ表示・操作検証結果

Headless Chrome（CDP 経由）にて、全3案の `1280x800`（基準サイズ）および `1100x700`（最小ターゲットサイズ）におけるレンダリング・DOM オーバーフロー・インタラクション動作を検証しました。

- **共通サンプルデータ**: 3案すべてで同一の日本語ファイルツリー（`PC > ローカル ディスク (C:) > ユーザー > aoi > ドキュメント`、通常表示 18 項目 ＋ 隠しファイル `desktop.ini` 1 項目、サブフォルダ 5 個・ファイル 14 個、および `ダウンロード` / `ピクチャ` / `ワークスペース` / `データ (D:)`）を共用し、直接比較可能にしています。
