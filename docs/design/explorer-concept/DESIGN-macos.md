# Explorer コンセプト（macOS寄りの配色案）— 変更メモ

モック: [concept-macos.html](./concept-macos.html)。前回の [concept.html](./concept.html) / [DESIGN.md](./DESIGN.md) は変更していない。
レイアウト・寸法・情報密度・機能は前回のまま。変えたのは**色と境界の付け方**だけ（例外: メニューの現在項目の扱いとアイコン表示の選択の見せ方。どちらも色の変更に合わせて調整した）。

## 1. 何がダサく見えていたか（仮説の検証）

前回の画面を並べて見ると、親の仮説（黄フォルダー＋強い青＋灰色＝古いWindows感）はおおむね当たっていた。ただし原因は黄色そのものより、**UIの側が青を薄く何か所にも撒いていたこと**だった。

| 前回 | 古く見える理由 |
|---|---|
| 灰色にわずかな青み（`#f3f3f5`、`#5c5c65`） | 黄フォルダーと補色関係になり、黄色と青の対比が目立つ |
| 青を淡く多用（選択・メニューのハイライト・使用量メーター・トグルON文字・サイドバー左端の線） | 「アクセントが1色」でも、出てくる場所が多いので画面全体が青っぽい |
| 白い入力欄＋濃い枠線（パンくず・検索） | Win32 / Windows 10の入力欄の作り方 |
| サイドバー現在地の左端3pxバー | Windows 11の設定やエクスプローラーの印 |
| 使用量メーターの青と赤 | 一覧の外にも原色が2つ出る |

試作メモの切替で黄フォルダーのまま（Windows風の仮素材）にしても、下の変更で古い印象は消えた。つまり**OSアイコンの色を変えなくても成立する**。

## 2. 方針

**「無彩色の面と文字の階層で組み、青は少ない場所でだけはっきり使う」**

- 面はすべて**R=G=B の無彩色**（青み・黄みなし）。全体をベージュにはしない。
- 青を使うのは次の4つだけ：**選択（一覧にフォーカスがあるとき）・メニューの現在項目・フォーカスリング・検索欄のフォーカス**。どれも塗りで、白い文字を載せる。
- それ以外の状態（ホバー・押下・現在地・トグルON・選択でフォーカスなし）は**灰色の重ね**で表す。
- 境界線は弱くし、層の区別は面の明るさの差に任せる。入力欄は**枠なしの塗り**にした。
- ブラー・グラデーション・タイトルバーの模写・丸ボタンは使わない。

## 3. 主な変更（トークン）

| トークン | 前回 ライト / ダーク | 今回 ライト / ダーク | 意図 |
|---|---|---|---|
| `bg-chrome` | `#f3f3f5` / `#202023` | `#f0f0f0` / `#2a2a2a` | 無彩色にし、一覧との明るさの差を少し大きく |
| `bg-content` | `#ffffff` / `#19191b` | `#ffffff` / `#1e1e1e` | ダークの青みを抜いた |
| `bg-field` | `#ffffff`＋枠 `#cfcfd5` | `#e4e4e4` / `#363636`、枠なし | 枠ではなく塗りで入力欄だと分かるように。フォーカス時は白地＋青リング＋淡い外側の輪 |
| `bg-selected` | `#dbe6fb` / `#213659` | **`#0a63d6` / `#0a58c8`＋白文字** | 選択ははっきりした塗り（Finderの一覧と同じ作法） |
| `bg-selected-inactive` | `#e9e9ec` / `#2b2b30` | `#e0e0e0` / `#3a3a3a` | フォーカスがない選択は灰色 |
| `bg-menu-hover` | `#e3ebfb` / `#26344f` | 選択と同じ青＋白文字 | メニューの現在項目 |
| `text` / `text-muted` | `#1c1c20` / `#5c5c65` | `#1d1d1f` / `#626266`（ダーク `#e6e6e8` / `#a6a6ab`） | 無彩色の4段（本文・補助・無効・操作アイコン） |
| `border` | `#e2e2e6` / `#2e2e33` | `#e6e6e6` / `#333333` | 弱く、無彩色に |
| `meter` / `meter-warn` | 青 / 赤 | 灰 `#8a8a8e` / 橙 `#e07b10` | 通常時は色を出さず、90%を超えたときだけ注意色 |
| 追加 | — | `text-on-selected`, `text-muted-on-selected`, `focus-on-selected`, `match-on-selected`, `text-on-menu`, `bg-seg-on`, `bg-button(-hover/-pressed)`, `bg-well`, `focus-halo`, `shadow-button` | 塗りの選択の上に載る文字やリングの色と、ボタン・プレビュー枠の面 |

そのほかの変更：
- サイドバーの現在地は左端のバーをやめ、灰色の塗りと太字（600）だけにした（色だけに頼らない手がかりとして太字は残す）。
- プレビュー枠とテキストプレビューは枠線をやめ、`bg-well` の塗りにした。
- ボタンは `bg-button`＋弱い枠＋1段の影。ホバーで青くしない。
- セグメントのONはダークで一覧面より明るい `bg-seg-on`（前回は一覧面と同じ色で、ONなのに沈んで見えた）。
- ステータスの「隠しファイル」がONのときは、青い文字ではなく押下と同じ灰色の塗り。
- 選択行の検索一致は、黄色ではなく選択色を暗くした帯（白文字のコントラストを保つため）。

## 4. 色の変更に合わせた小さな挙動の変更

- **メニュー**：マウスで開いたときは、どの項目も青くしない（ホバーした項目が現在項目になる）。キーボード（Shift+F10 / アプリケーションキー）で開いたときは前回どおり先頭項目が現在項目。ホバーとキー操作は同じ「現在項目」を共有するので、青い項目が2つ同時に出ることはない。理由：青い塗りは強いので、開いた瞬間に関係のない項目が青くなるのを避けた。
- **アイコン表示（塗りの選択のとき）**：タイル全体を青くせず、アイコンの背後に灰色の角丸、名前に青い角丸の帯を敷く（Finderのアイコン表示の作法）。48pxのOSアイコンが青い地に載らないので、アイコンの色を選ばない。

## 5. 検証用の切替（試作メモ内）

- **ファイルアイコンの仮素材**：Windows風（前回の仮素材、既定）/ macOS風（今回の仮素材）。macOS風は淡い青のフォルダー、種別色をページの内側に収めた帯、銀色のドライブ。
- **選択の表現**：塗り（既定）/ 淡色（前回に近い淡い青、通常の文字色）。

どちらの仮素材も実装では使わない。本番は前回の合意どおり**OSのアイコンをそのまま表示し、減色・単色化はしない**。操作アイコンは前回どおり単色（`currentColor`）。
4通りの組み合わせ × ライト/ダークをすべて描画して、UI側の配色がアイコンの色を選ばないことを目視で確認した。黄フォルダーとの組み合わせで少し色数が増えて見えるのはOSアイコン側の性質で、UIの配色で打ち消すべきものではないと判断した。

## 6. GPUIへの移し方（前回との差分）

- `Theme` に追加：`bg_field`（塗り）, `bg_seg_on`, `bg_button`, `bg_button_hover`, `bg_button_pressed`, `bg_well`, `text_on_selected`, `text_muted_on_selected`, `focus_on_selected`, `match_on_selected`, `text_on_menu`, `text_muted_on_menu`, `focus_halo`。
- 選択行は背景だけでなく**文字色も切り替える**（`focus_handle.contains_focused(..)` が真で選択中なら `text_on_selected` / `text_muted_on_selected`）。行を描くときに選択状態を1回求め、セルごとの文字色に渡す。
- 入力欄のフォーカスは `.border_1().border_color(focus)` と、外側の輪を表す `BoxShadow`（spread 3px, `focus_halo`）の1つ。
- 検証用の切替（仮素材・選択の表現）はモック専用で、実装には持ち込まない。選択の表現をユーザー設定にするかは未決。

## 7. 確認したこと

前回と同じヘッドレスChrome（`--remote-debugging-pipe`、HTTPサーバーなし）で確認した。

- **回帰（前回の検査一式）**：選択・範囲選択・ソート・検索（一致/0件/クリア）・詳細ペインの開閉・フォルダー移動と戻る/上へ・隠しファイル・サイドバー移動・右クリックメニュー・設定メニューからのテーマ切替・アイコン表示・試作メモ・1100×700 / 900×600 / 1440×900で横スクロールなし。すべて期待どおり。ページ上のJSエラーなし。
- **追加の検査**：マウスで開いたメニューに現在項目がない／ホバーで青くなる／↓で次の項目へ進む。
- **コントラスト**（ライト/ダーク × 塗り/淡色）：計128組がすべて基準以上（文字4.5:1、アイコン・フォーカスリング3:1）。
  - 選択の上の白文字：ライト 5.57 / ダーク 6.48、選択の上の補助文字：4.77 / 5.20
  - `text-muted` の最小：ライト 4.60 / ダーク 4.69（どちらもフォーカスなしの選択の上）
  - 入力欄の塗りの上のプレースホルダー：4.78 / 4.99
  - フォーカスリングの最小：3.38（ダーク、フォーカスなしの選択の上）
- **目視**：1280×800のライト/ダーク × 仮素材2種 × 選択の表現2種、メニュー（ホバー中）、範囲選択とキー操作のリング、選択行の検索ハイライト、アイコン表示（フォーカスあり/なし）、画像・テキストのプレビュー、設定メニュー、試作メモ。

未確認：前回と同じ（実機のWindows / macOSでの描画、スクリーンリーダー、Firefox / Safari）。
