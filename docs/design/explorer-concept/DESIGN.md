# Explorer コンセプト — 設計メモ

モック: [concept.html](./concept.html)（単一ファイル・ネットワーク不要・ビルド不要）。
ファイルはすべてサンプルデータ。OSのAPIは呼んでいない。ファイル・フォルダー・ドライブのカラーアイコンは、OSから取得するアイコンの**代用として描いた仮の絵**。

## 1. コンセプト

**「静かな作業面、主役はファイル」**

- 常用のシステムツール。ブランドの主張はほぼゼロで、タイトル・ロゴ・ヒーロー・カードは置かない。
- 層は**面の明度差**で作る。クローム（ツールバー/サイドバー/ステータス）は薄いグレー、一覧は最も明るい（ダークでは最も暗い）面。境目は1px罫線。
- 色を持つのは「もの」（OSのファイル/フォルダー/ドライブアイコン）とアクセント1色だけ。操作アイコンは単色線画。この区別が「カラーと単色の混在」を自然にする。
- GPUIで再現しやすい要素だけを使う：塗り、1px罫線、角丸、影1〜2段、文字の大きさ/太さ/色。ブラー・常時アニメーション・グラデーションは使わない（トランジションも無し）。

タイトルバーはPoCと同じくOS標準を想定（カスタムタイトルバーはOS差が大きいので今回は扱わない）。

## 3. デザインシステム（小）

トークンの正本は `concept.html` 冒頭の `:root` / `:root[data-theme="dark"]`。

- 選択色は**不透明色**にした（重なり順に依存せずGPUIで扱いやすい、コントラストが計算どおりになる）。
- `text-disabled` は無効状態専用。意味のある文字には使わない。
- `obj-*`（フォルダー・各ファイル種別・ドライブ）はOSアイコンの代用色で、実装では消える。

**コントラスト（ヘッドレスChromeで算出）**：`text` は全面で 9.89:1 以上（検索ハイライト上でも 6.96:1）、`text-muted` は全面（選択・ホバー・メニューハイライト上を含む）で 4.5:1 以上（最小: ライト 5.27 / ダーク 4.89、どちらも選択面上）、`accent` 文字は 4.94:1 以上、フォーカスリングは選択面上でも 4.36:1。

日付・サイズ列は等幅数字（`tabular-nums`）。大見出しは作らない。

### 余白・角丸・影

- 余白は4px基準：`2 / 4 / 6 / 8 / 12 / 16 / 24`（`sp-1`〜`sp-7`）。
- 角丸：`r-sm 4px`（小ボタン・メニュー項目）/ `r-md 6px`（行・ボタン・入力欄）/ `r-lg 8px`（メニュー・ダイアログ・プレビュー枠）。
  連続して選択された行は接する側の角丸を0にして1つの塊に見せる。
- 影は浮く面だけ：`shadow-xs`（セグメントのON）/ `shadow-popover`（メニュー: 0 6 18 12% + 0 1 3 8%）/ `shadow-dialog`。一覧や詳細ペインには影を付けず罫線で区切る。

### アイコン

- **操作アイコン**（戻る・進む・上へ・更新・検索・表示切替・詳細ペイン・設定・閉じる・目・情報など）：24pxグリッド、線幅1.75、丸端・丸結合、`currentColor` の単色。16px表示が基本。
  モックのパスはLucideの作法に合わせて**自作**したもの（PoCの `apps/explorer/assets/icons/*.svg` と同系統）で、Lucideのコードは含まない。実装でLucide本体に置き換えるなら必要分だけ取り込み、ISCライセンス文をリポジトリに同梱する。
- **オブジェクトアイコン**（ファイル・フォルダー・ドライブ・特殊フォルダー）：OSから取得したカラービットマップ。16px（一覧・サイドバー・パンくず）、48px（アイコン表示）、64px（詳細ペイン）。
- 絵文字はアイコンに使わない。

### 操作状態

| 状態 | 表現 |
|---|---|
| ホバー | `bg-hover` を敷く（行・ボタン・パンくず・サイドバー） |
| 押下 / トグルON | `bg-pressed`。セグメントのONは `bg-content` + `shadow-xs` |
| 選択 | 一覧にフォーカスがあれば `bg-selected`、なければ `bg-selected-inactive`（メニュー表示中はフォーカスあり扱い） |
| キーボードフォーカス | 2px `focus` リング。一覧はアクティブ行の内側に角丸リング（キー操作時のみ、マウス操作で消える） |
| 現在地 | サイドバー項目に `bg-nav-active` + 左端3pxの `accent` バー + 600。パンくず末尾は `text` + 600 |
| 無効 | `text-disabled`（例: 戻れないときの戻るボタン） |
| 隠しファイル | 名前を `text-muted`、アイコンを半透明 |
| 空 / 不一致 | 一覧の中央に1行の説明（不一致時は「検索をクリア」ボタン） |

## 4. モックで動くもの

- 行選択（クリック / Ctrl / Shift / Ctrl+A / Esc）、↑↓ Home End PageUp/PageDown（Shiftで範囲、Ctrlでフォーカスのみ、Spaceで切替）
- フォルダー移動（ダブルクリック / Enter / パンくず / サイドバー）と戻る・進む・上へ（選択を復元）
- 検索フィルター（Ctrl+F、全角半角・大小文字を同一視、一致部分をハイライト、Enterで一覧へ、Escでクリア）
- 列見出しでソート（フォルダーは常に先頭、2回目で降順）
- 詳細ペインの開閉（Alt+P）と内容の切替（未選択=現在のフォルダー / 1件 / 複数件、画像とテキストの簡易プレビュー）
- 表示切替（詳細 / アイコン）、隠しファイル（Ctrl+H）、行の高さ（標準/コンパクト）
- 右クリック / Shift+F10 のコンテキストメニュー、設定メニュー（テーマ：システム/ライト/ダーク）
- ステータスの件数は常に描画行数と一致（検索時は「19 項目中 1 項目が一致」）

動かないもの：名前の変更・コピー・切り取り・削除・新規フォルダー（メニューの見た目のみ。選ぶとステータスに「動作しません」と出る）、ファイルを開く、列幅変更、ドラッグ。

**試作専用の層**：ステータスバー右端の点線ボタン「試作メモ」だけ。押すとダイアログで注意書き・現在のトークン値・キー一覧を表示する。テーマ切替はアプリ本来の設定（⚙）に置いた。

## 5. GPUIへの移し方

| モック | GPUI |
|---|---|
| CSS変数 | `theme.rs` の `Theme` に同名フィールドを追加（`bg_chrome`, `bg_content`, `bg_pane`, `bg_field`, `bg_elevated`, `bg_track`, `bg_hover`, `bg_pressed`, `bg_selected`, `bg_selected_inactive`, `bg_menu_hover`, `border`, `border_strong`, `text`, `text_muted`, `text_disabled`, `icon`, `accent`, `focus`, `meter`, `meter_warn`, `match_bg`）。寸法は `explorer.rs` 冒頭の `const` 群（`ROW_HEIGHT` などPoCと同じ書き方）に集約 |
| `prefers-color-scheme` + 手動切替 | 既存の `observe_window_appearance` に加えて `ThemeMode { System, Light, Dark }` を設定に持つ |
| 罫線・角丸・面 | `.border_1()` / `.border_color()` / `.rounded(px(6.))` / `.bg()` |
| 影 | `.shadow(vec![BoxShadow { .. }])`（メニュー・ダイアログだけ） |
| 一覧 | 既存の `uniform_list`（行高固定28/24px）。列は固定幅 + `flex_1` の名前列 |
| アイコン表示 | 列数 = 幅 / `w-tile` を描画時に計算し、`uniform_list` の1行に複数タイルを並べる |
| 選択色の切替 | `focus_handle.contains_focused(window, cx)` で active/inactive を選ぶ |
| フォーカスリング | アクティブ行に `.border_2().border_color(theme.focus)`（キー操作フラグが立っているときだけ） |
| 操作アイコン | `svg().path("icons/x.svg").size(px(16.)).text_color(theme.icon)`（PoCと同じ。埋め込みSVG） |
| OSアイコン | Windows: `SHGetFileInfoW` / `IShellItemImageFactory` で取得したHICONまたはHBITMAPをRGBAに変換、macOS: `NSWorkspace.icon(forFile:)`。一般的な種類アイコンは共有し、実行ファイル・ショートカット・カスタムフォルダー等の固有アイコンはパス/識別子とサイズ・DPIを考慮して別途キャッシュし `img()` に渡す。列挙を遅延させない専用バックグラウンド処理で表示範囲を優先して取得し、届くまでは汎用アイコン |
| 表示名 / 実パス | パンくずとサイドバーはOSのローカライズ表示名（例「ドキュメント」）、詳細ペインの「場所」とパスのコピーは実パス（`C:\Users\aoi\Documents`） |
| メニュー | `deferred(anchored(..))` + 独自のメニュー要素。キー操作（↑↓ Enter Esc）はアクションで |
| 狭い幅の列落とし | 描画時に一覧領域の幅を見て列を `.when(..)` で外す |
| 数字の桁揃え | `FontFeatures` で `tnum` を指定 |
| ドライブ使用量 | 4px高の溝 + 幅比率の塗り（`div` 2つ） |

WebView等のGPUI Fast専用機能には依存しない（プレビューも画像デコード + テキスト先頭数行で足りる範囲）。

## 6. 試作上の仮決め

- フォルダーは昇順・降順どちらでも先頭（Windowsの降順時の挙動とは違う）。
- 日付は `2026/11/14 9:41` の絶対表記。「今日」などの相対表記は未検討。
- サイズは1024進でKB/MB/GB、100未満は小数1桁。フォルダーのサイズは一覧に出さない。
- 種類名は「XLSX ファイル」のような拡張子ベース。実装ではOSの種類名（`SHGetFileInfoW` の `szTypeName` 等）に置き換える想定。
- 作成日時はサンプル用の仮値。
- 検索は現在のフォルダー内の名前フィルターのみ。サブフォルダー検索・インデックス検索は未検討。
- 行の高さ「コンパクト」(24px) は密度設定の候補として入れただけ。
- タブ、カラム幅変更、ドラッグ&ドロップ、アドレス欄の直接入力、ファイル操作の確認/進捗UIは今回の範囲外。

## 7. 確認したこと

ヘッドレスChrome（`--remote-debugging-pipe`。HTTPサーバーは起動していない）で 1280×800 / 1100×700 / 900×600 / 1440×900、ライト/ダークを描画し、次を確認した。

- 選択・範囲選択・ソート・検索（一致/0件/クリア）・詳細ペイン開閉・フォルダー移動と戻る/上へ・隠しファイル・サイドバー移動・右クリックメニュー・設定メニューからのテーマ切替・アイコン表示・試作メモの開閉：すべて期待どおり
- すべての画面で描画行数とステータス件数が一致
- 全サイズで横スクロールなし・ツールバーがはみ出さない（900px幅では一覧領域が狭くなり「種類」列を落とす）
- 上記コントラスト値、ページ上のJSエラーなし

未確認：実機の Windows / macOS 上での描画（フォントの字幅、高DPI）、スクリーンリーダーでの読み上げ、Firefox / Safari。
