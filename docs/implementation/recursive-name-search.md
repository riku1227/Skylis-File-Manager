# フォルダー以下を名前で検索

検索欄は名前の部分一致（大文字小文字を区別しない）で絞り込む。「このフォルダー」は直下の全一致結果、「サブフォルダー内」は2階層目以降の一致結果。配下には相対的な親フォルダーを表示し、同名でも実際のフルパスで扱う。検索中は一覧表示になり、クリアすると選んでいた表示形式に戻る。ホーム・書庫内は従来の直下フィルター。

直下は従来どおり選択・範囲選択・名前変更・削除・コピー／切り取り／貼り付け・作成・ドラッグなどを使える。配下は単一選択で、開く、フォルダーを新しいタブで開く、親フォルダーで表示、パスをコピーに対応する。編集は親フォルダーで行う。配下から作成や貼り付けをして検索元へ操作が流れることはなく、配下の行・見出し・背景はドロップ先にならない。詳細ペインを隠していても、選んだ配下の操作は下のバーで使える。

直下のフィルターは入力と同時に更新し、IMEの未確定文字にも追従する。配下は変換確定後250ms待って開始する。確認済みのローカル固定ディスク以外は、検索語ごとに「配下の検索を開始」を押す。停止・タブ切替後も受け取った行は残り、再開は手動。入力変更、場所移動、隠しファイル変更、更新では古い要求を無効にする。通常の監視更新は配下を再走査しない。配下は常にスナップショットで、最新情報は再検索する。

## 負荷と探索範囲

- プロセス全体で固定2ワーカー。確認済みローカル用と、場所の分類／明示開始用を分ける。OS内で待っている読み取りの代わりにスレッドを増やさない。同じタブは古い処理が戻るまで同時実行しない。
- 待機最大8件、保持する結果ストリーム最大8件、タブごとに最新の待機要求1件。結果チャネルは2バッチ。完了後のスナップショットは各タブに残るため、保持する結果の総量は検索済みタブ数に比例する。1バッチ64件／256KiB、ビューは取り込みごとに16ms譲り、全窓で2msの協調的な予算と順番を共有する。これはハードリアルタイムの上限ではなく、64件の取り込み単位で予算を超える可能性がある。
- 配下は確認10万entry、結果5000件、結果payload 8MiB、深さ64、パス32KiB、探索経路512KiB、受付から30秒で制限する。上限やスキップ数を表示し、完全な結果と誤解させない。直下フィルターには件数上限を付けない。
- DFSでリンク先・別ボリュームをたどらない。隠しファイルを表示しない場合は隠しフォルダーの中にも入らない。Windowsではメタデータ用ハンドルでタグを確認し、通常のローカルクラウドタグは許可、リンク・ジャンクション・未知タグ・offline／recall対象を除く。ルートの中間ジャンクションを解決してからローカル判定する。macOSはdevice／inodeとdataless属性を確認する。
- 探索はファイル内容、画像、Shellアイコン、プロパティ、再帰サイズを読み込まない。配下は表示中の行だけ既存ワーカーで種類別アイコンを取得し、実ファイルのアイコンやサムネイルは問い合わせない。[一致箇所の強調とアイコン](search-result-presentation.md)を参照。クラウドのメタデータ照会自体がプロバイダーの通信を起こす可能性は残る。
- キャンセルはOS呼出しの間で協調的に行う。停止表示になっても、OS内で詰まった読み取りを強制中断したとは限らない。送信待ちはワーカー自身も共通期限を確認する。

## 検証

- `cargo test --locked --workspace --quiet`: 361 passed、3 ignored（実環境向けの既存2件と手動性能診断1件）。
- `cargo build --release --locked --target x86_64-pc-windows-msvc`: 成功。既存の未使用import／Windowsでは使わないmacOS補助関数の警告2件は残る。
- `cargo check --locked --target aarch64-apple-darwin -p explorer-core`: 成功。macOSアプリ全体のビルド／GUI確認は含まない。
- `cargo fmt --all -- --check`、`git diff --check`: 成功。


自動テストは、直下フィルターの伸長と一覧変更、配下のみの一致、Unicode、件数／容量／深さ／経路上限、隠し項目、キャンセル、FIFO終端、満杯チャネル、明示レーンのブロック中のローカル進行、同じタブの非並行、パニックからの復帰、古い世代の拒否、IME確定、タブ非表示後の読み込み完了、配下選択からの操作拒否を扱う。CIでは経過時間の閾値をassertしない。

直下の実モデル診断は `cargo test --release --locked -p explorer direct_filter_100k_diagnostic -- --ignored --nocapture`。Ryzen 7 5700X・Windows・Rust 1.100.0、10万Entry、各検索語41回で測定し、最初の改善後の4条件で最大3.72msだった。一覧モデルの絞り込みと行索引の時間であり、ネイティブ描画・GPUフレーム時間を含まない。前段の文字列fixture測定と区別する。

Windowsの起動・通常画面と、描画／クリックを伴うheadlessテストは確認した。検証ウィンドウへの手動入力を検出したため、画面の自動操作は中断している。検索中のGPUフレーム時間、OSレベルのドロップ、実際のSMB停止、クラウドタグ付きOneDrive、ネイティブIME候補配置、macOSのGUIは未確認。macOSのcoreは `cargo check --locked --target aarch64-apple-darwin -p explorer-core` でクロスコンパイル確認した。この環境のOneDriveルートは通常のディレクトリ属性で、クラウドタグの実物確認には使えなかった。

完成レビューではmacOSのtrait／型指定と、同じアクティブタブへのswitchで検索を止める箇所、背景タブのドラッグ／切り離しでの切替処理、破棄時のopen中断を指摘され、修正と回帰テストを追加した。修正後のOpus再レビューで重要な指摘は残っていない。設定を開く／閉じる際の停止・可視化は明示的なイベントで扱い、renderから状態を推測しない。

統合後の再測定（同条件、描画を含まない）では project p50/p95/max 2.832/3.452/3.923ms、長い検索語 3.074/3.673/3.842ms、日本語 2.313/2.969/3.761ms、非一致 2.523/3.351/3.581msだった。これはこのホストの診断値であり、大規模フォルダーの列挙マージや150Hzでのフレーム維持を保証しない。

Windowsのメタデータ用アダプターも長いパスに対応させ、UNC・非Unicode UTF-16・`..`の解決順と、260文字を超える実フォルダーの探索をテストした。末尾空白・ピリオドなど特殊なWin32名の振る舞いは未検証。
