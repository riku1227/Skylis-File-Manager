# 日常利用向けのファイル操作

2026-11-15。通常のフォルダー操作、外部変更の反映、圧縮ファイルの閲覧・作成・解凍を追加した時点の実装範囲。設計上の対応と、実画面で確認した内容を分けて記録する。

## 操作できること

| 操作 | 実装した動作 |
| --- | --- |
| 名前の変更 | F2または右クリックから、一覧行・ギャラリーの名前を入力欄に切り替える。ファイルは拡張子を除く部分を選択。Enterで確定、Escapeで中止。日本語の変換中は確定・中止しない。 |
| 新規作成 | フォルダーとテキストファイルを作成できる。同名項目を上書きしない。 |
| 削除 | WindowsではDeleteでごみ箱、Shift+Deleteで完全削除。破棄の確認・権限エラー・中止はWindowsのファイル操作UIを維持する。黙って完全削除へ再試行しない。 |
| コピー・移動 | Windowsの`IFileOperation`を使用。Skylisにも進捗を表示し、競合・権限・キャンセルはWindowsのUIで扱う。完了・中止・途中失敗後は関係するタブの一覧を更新する。 |
| パスとプロパティ | 選択項目のパスをコピーできる。Windowsのプロパティ画面も開ける。 |
| 外部変更の反映 | ローカルフォルダーのOS通知をまとめ、更新後の一覧をバックグラウンドで準備する。既存の行を途中で消さず、検索語・残存項目の選択・スクロール位置を保って差し替える。 |
| ZIP・7zの閲覧 | 圧縮ファイルをダブルクリックすると、読み取り専用の仮想フォルダーとして開く。内部フォルダーの移動、戻る・進む・上へ、検索・選択に対応する。 |
| 解凍 | 圧縮ファイル全体、または内部で選択した項目を解凍できる。指定先に新しいフォルダーを作り、同名時は番号を付ける。 |
| 圧縮 | 選択したファイル・フォルダーからZIPまたは7zを作る。元の項目を残し、既存の出力は上書きしない。 |
| 処理の表示 | 圧縮・解凍は実行中・待機中・完了・失敗をアプリ内で表示し、キャンセルできる。完了履歴は最大16件を保持する。 |
| ウィンドウ | 新しいウィンドウを開ける。タブを別ウィンドウへ移した場合も、非同期処理の結果を現在の表示先へ戻す。入力途中のダイアログは維持する。 |

ファイルのドロップ方針は[ドラッグとドロップ](drag-drop.md)を参照。同一アプリ内では同じボリュームの移動・別ボリュームのコピーを基本とし、Ctrlでコピーを選べる。外部アプリからのドロップはコピーとして扱う。ピン留めとHome表示は[フォルダー連携とピン留め](folder-integration-and-pins.md)に記録している。

## 外部アプリとExplorer

- 通常のフォルダーを開く関連付け、Win+E、Explorerの背景メニュー「Skylisへ切り替え」は、独立した設定と復元記録を持つ。
- Explorerの自動クローズは、呼び出し元のウィンドウ・ビュー・フォルダーが一致し、単一タブを確認でき、Skylisの一覧読み込みも成功した場合に限る。確認できなければExplorerを残す。Explorer全体を強制終了しない。
- `--select "対象の絶対パス"` は、親フォルダーを開いて対象名を選択する明示的な受け口。
- 調査したT3 Codeの既定ハンドラー経路は、Skylisへ**親フォルダーだけ**を渡す。ファイル名が渡らないため、対象ファイルの自動選択まではできない。
- Files型の`IShellWindows` / `IShellView::SelectItem`選択ブリッジは調査段階で、今回の実装には含めない。任意の`explorer.exe`直接起動や、ファイル選択・保存ダイアログも置き換えない。

呼び出し元の版・経路による差、復元条件、選択ブリッジの追加案は[T3 RevealとExplorer切り替えの調査](../research/t3-reveal-and-explorer-handoff.md)、Filesの実装との比較は[Filesの標準ファイルマネージャー調査](../research/files-default-file-manager.md)を参照。関連付けの実装が存在することと、すべての外部アプリでの実機検証が済んでいることは区別する。

## バックエンドと状態の責任範囲

| 場所 | 責任 |
| --- | --- |
| `apps/explorer/src/file_operations.rs` と配下のアダプター | コピー・移動・削除の事前検証、Windowsのネイティブ処理、進捗通知。共通で1操作まで。受信タブを閉じても開始済み操作を途中放棄しない。 |
| `apps/explorer/src/folder/name_operations.rs` | ワーカー上での作成・名前変更。OSの上書きなし操作を使い、名前が同じ場合も元の存在を確認する。 |
| `apps/explorer/src/directory_watch.rs` | 非再帰のOS監視。監視の生成・終了はUIスレッド外。最大32監視、通知キューは1件。200msの静止時間でまとめ、連続変更も最大1秒で通知する。 |
| `apps/explorer/src/folder/watch.rs` | 完全な一覧スナップショットの取得と反映。更新ワーカーは全体で最大4件。編集中・メニュー中・ドラッグ選択中などは反映を延期し、次の更新要求を1件にまとめる。 |
| `crates/explorer-core/src/archive` | UI非依存の解析・圧縮・解凍。パス・サイズ・形式の検証、キャンセル、ステージングと上書きなし公開。 |
| `apps/explorer/src/archive_jobs.rs` | アプリ共有の圧縮操作。内容処理1件＋待機4件、内容確認1件＋待機8件、履歴16件。タブ移動・画面切り替えから処理寿命を分離する。 |
| `apps/explorer/src/folder/archives.rs` | 圧縮ファイル内の表示、保存先入力、選択したメンバー、ジョブ表示。仮想メンバーを実ファイルの変更先として扱わない。 |
| `FolderView::owner_window` / `with_owner` | タブの現在のホストウィンドウを保持する。移動後の初回描画前でも、ファイルを開く処理・名前変更・解凍準備の完了を正しいウィンドウへ返す。 |
| `apps/explorer/src/file_open.rs` | 既定アプリ起動とリンク先の確認をUI外へ移す。待機は4件まで。WindowsではSTAを初期化する。 |
| `folder_integration.rs` / `shell_handoff.rs` | Windowsの登録・復元と、明示的なExplorer切り替え。通常の一覧・圧縮処理とは分離する。 |

圧縮形式・コーデック、メンバー数、展開サイズ、辞書・解析メモリーの上限、WindowsのZone.Identifierの扱い、依存ライブラリとローカル修正は[archiveバックエンドREADME](../../crates/explorer-core/src/archive/README.md)を正本とする。

## 残る制限

- 圧縮ファイル内は読み取り専用。名前変更・削除・貼り付け・直接編集・直接プレビューは行わず、内容を利用するときは解凍する。パスワード付き・分割アーカイブ・未対応形式／コーデックはエラーとして示す。
- コピーエンジンはWindows標準を使う。独自エンジンより速いという比較結果はなく、Skylis内のキャンセル操作やUndoコマンドも未実装。進捗はWindowsが返す作業量であり、転送バイト数とは限らない。
- UNC・WSL・ネットワークドライブの自動監視は行わず、F5で更新する。監視開始に失敗した場合もポーリング走査へ置き換えない。
- macOSのごみ箱処理はFinder経由。完全削除は未対応。今回のWindows実機結果をmacOSの検証済み結果として扱わない。
- ネイティブファイル操作中のウィンドウ終了と、所有元ウィンドウを消すタブ移動・統合は保留する。圧縮操作中の終了も、完了またはキャンセルを待つ。
- 同一ユーザー権限の別プロセスによる競合書き換えまで完全に隔離する仕組みではない。圧縮の公開・検証範囲はバックエンドREADMEに記載する。

## 確認した内容

Windowsの実画面では、次を確認した。

環境はWindows 11 Home、ビルド26300。最終の`cargo test --locked --workspace`は272成功・既存のプラットフォームスモークテスト2件を無視。`cargo fmt --all -- --check`と`git diff --check`も成功。`target/release/skylis-final.exe`を別名でビルドし、既に使用中の実行ファイルは置き換えていない。実行ファイルは19,075,584バイト（今回の機能追加前16,528,896バイト）。全機能差分の測定値であり、圧縮ライブラリ単独の増加量ではない。

- 日本語を含む行内名前変更後に`.txt`拡張子とファイル内容が保たれる。
- .NETで別途作成したZIPを閲覧・解凍でき、日本語名と空フォルダーが保持される。
- コンテキストメニューから作成した7zを7-Zip 23.01の`7z t`で検査し、`Everything is Ok`となる。
- 作成された結果と外部アプリが追加した項目が、F5なしで一覧へ反映される。
- ZIPの作成も7-Zipで正常判定。7zをダブルクリックして閲覧・解凍し、日本語テキストとバイナリのSHA-256が元と一致する。
- Ctrl+Shift+Nで新規フォルダーを作成。Alt+Enterでプロパティを開き、元タブを閉じてもプロパティが残る。最後のウィンドウの終了はプロパティを閉じるまで保留する。
- コピー進捗の表示、Windowsの同名衝突ダイアログ、衝突時のキャンセルを確認。コピー後の内容ハッシュが元と一致する。
- Shift+Deleteで完全削除の確認が表示され、Escapeで取り消すと元の内容が残る。Deleteではテストファイルが実際にごみ箱へ移動したことをShellのごみ箱一覧で確認する。
- `--select`は対象の隠しファイルだけを表示・選択し、別の隠しファイルや全体の表示設定を変えない。
- Explorer背景の「Skylisへ切り替え」で、単一タブは一覧読み込み後に元ウィンドウが閉じる。2タブの場合は両方を残し、理由をSkylisに通知する。
- Win+Eと切り替えメニューの登録・復元を設定画面から実行。復元後に登録値とメニューが消え、既存のフォルダー関連付けが保たれる。Win+Eキーそのものの押下は自動検証していない。

最終レビューで、一覧更新が計算済みサイズと進行中の計算を破棄する問題を修正した。残っているディレクトリの結果と処理を維持し、消えたパスだけを中止する。削除後に同名の項目が現れても古い計算結果を受理しない。F5は初回読み込み中ならその読み込みを取り消して再試行する。圧縮内のインスペクタでは内部位置と実パスを区別し、実パスのコピー操作を表示しない。

プロパティの実機確認では、画面を閉じた後も非表示のIME補助ウィンドウが残り、処理中フラグが解除されない問題も検出した。表示中のプロパティ画面だけを待つよう修正し、実Win32ウィンドウを使う回帰テストで非表示の所有ウィンドウが待機を延長せず、ワーカーの終了処理が戻ることまで確認した。この最後の修正後の実画面再確認は、利用者がEscでComputer Useを停止したため実施していない。GUI操作を再開せず、コード・回帰テスト・リリースビルドの検証までを完了範囲とする。

自動テストでは、削除対象の検証と親子重複除去、Windowsの破棄確認フラグ、OS監視通知・集約・キャンセル、一覧の選択／検索／スクロール保持、編集中の更新延期、Windowsの大小文字だけの名前変更、IMEとDeleteの入力処理を確認する。圧縮コア・操作キューの検証範囲はバックエンドREADMEを参照。

主要な検証コマンド:

```text
cargo test --locked -p explorer
cargo test --locked -p explorer-core
cargo check --locked -p explorer
```

Explorer切り替えの全Windows版・全呼び出し元、選択ブリッジ、実アカウントでのOneDrive hydration、実FAT/exFATドライブ、macOS実機の包括的な動作確認は、上記の実画面確認には含めない。キャンセル通知は複数項目の一部完了を否定しない文面にしている。ファイル操作中の終了保護は現状、複数ウィンドウにも保守的に適用する。
