# モーションシステム

ファイル操作を待たせず、状態変化の手掛かりだけを示す。実装は `apps/explorer/src/motion.rs` と `apps/explorer/src/motion/presence.rs` にまとめる。既存のスクロール制御は変更しない。

## 原則

1. **いつでも割り込める。** 動作中に逆の操作が来ても、描画済みの位置と速度から続ける。先頭からやり直さない。
2. **入力は動きを待たない。** 開く操作は最初のフレームから入力とフォーカスを受ける。閉じる操作は論理的に即時で、残像だけが消えていく。
3. **消えるほうが速い。** 退場は必ず登場より短い。
4. **出どころを示す。** ポップアップはトリガー側から数px、モーダルは上から数px動いて現れ、同じ側へ戻る。
5. **動かさない場所を決める。** フォルダー移動、一覧・サムネイルの出現、スクロール、タブ切替の中身、ホバーには付けない。高頻度の操作を遅らせず、一覧の再レイアウトを増やさないためである。
6. **OSの動作低減を尊重する。** 有効時は最終状態を描き、フレームを要求しない。残像も残さない。

## トークン

動きは部品名ではなく役割で名付ける。同じ種類の面は同じ動きになる。バネはすべて臨界減衰（質量1、目に見える行き過ぎなし）で、目標変更時に速度を引き継ぎ、収束後はフレーム要求を止める。

| バネ | k / c | 99%到達の目安 | 用途 |
| --- | --- | --- | --- |
| `spring::SNAPPY` | 6400 / 160 | 約85ms | ポインター直下の小さな部品（スイッチ）と、すべての退場 |
| `spring::BRISK` | 3600 / 120 | 約110ms | 選択面（セグメント）、トリガーの隣に現れるメニュー・ポップアップ |
| `spring::SMOOTH` | 2304 / 96 | 約140ms | ウィンドウ全体を覆う面（モーダル） |

| 遷移 | 登場 | 退場 | 移動 |
| --- | --- | --- | --- |
| `MENU`（右クリックメニュー） | BRISK | SNAPPY | 不透明度のみ |
| `POPUP`（表示設定・検索条件） | BRISK | SNAPPY | 不透明度＋トリガー側から6px |
| `MODAL`（設定。背景と本体が同じ進行度を共有） | SMOOTH | SNAPPY | 不透明度＋上から8px。外枠は最終位置に固定 |

退場のない不透明度だけのフェードは時間で指定する。カテゴリ内容は90ms、詳細ペイン内容は開いたときだけ100ms、プレビュー窓は110ms。いずれもease-out cubic。詳細ペインの幅は即時に確定する。

## Presence：開閉の動き

`Presence<T>` は一時的な面の進行度（0＝不在、1＝表示）を1本のバネで持つ。所有者は毎フレームの描画の先頭で `sync(現在の内容, 遷移, 時刻, 動作低減)` を呼ぶ。開いている間は `Some(内容)`、閉じたら `None` を渡すだけでよい。

- 閉じる側のコードは何も知らなくてよい。`context_menu = None` のような既存の閉じ方を、描画時に観測して退場へ変える。
- 退場中は最後の内容を「残像」として描く。右クリックメニューは閉じた時点のコマンド一覧を保持する。元になった選択は既に変わっている可能性があるためである。
- 残像は操作できない。フォーカス追跡と外側クリックの処理を外し、最前面に `ghost_shield()` を置く。消えかけの面へのクリックは、古い部品を動かさず、下の画面にも抜けない。モーダルの残像は約75msの間ウィンドウ全体の入力を吸収する。
- 退場中に開き直すと、描画済みの不透明度と速度から登場に切り替わる。内容は新しいものに差し替わる。
- 待機していた時間は次の動きに算入しない。向きが変わったフレームは経過0として扱う。
- 描画前に開閉が完了した場合、残像は出ない。所有者の描画が止まった場合（タブ切替など）は、次の描画で経過時間ぶん進み、収束していれば外す。
- 残り2%で到達とみなして固定する。見えない尾のために残像とフレーム要求を数十ms延ばさない。
- フレーム要求は `sync` が `true` を返した間だけ、呼び出し側が `window.request_animation_frame()` で行う。独自のタイマーやフレームループは持たない。

表示設定ポップアップの残像は、現在のタブの状態から描く。閉じた直後にホームへ移動した場合などは、消える間に行構成が変わることがある。

## セグメントとスイッチ

受け皿に選択面を1枚だけ絶対配置し、選択番号÷選択肢数をleftの割合に使う（BRISK）。スイッチはノブとトラック色を同じスカラーで補間する（SNAPPY）。どちらも `with_spring` で、安定した部品IDに位置・速度が保存される。初回は目標位置から始まる。

移動は対象自身のrelative位置、選択面とノブはabsolute位置を使い、ファイル一覧・サイドバーのサイズ計算には参加させない。ポップアップの画面内制限と内部スクロールは従来の最終寸法で計算する。有効な画像を読み込み中表示に置き換えない。ファイル走査・デコード・再帰サイズ計算は追加しない。

## 検証

回帰試験で次を確認する。

- `Presence` 単体：登場は不在から始まる、待機時間を退場に算入しない、退場が登場より短い、反転時に位置を引き継いで内容を差し替える、動作低減と長い中断で残像を残さない、全遷移が0〜1を越えない。
- 設定モーダル：Escで即時に閉じた扱いになる、残像の「完了」ボタンをクリックしても何も起きない、収束後に外れてフレーム要求が0になる、退場中の開き直しが途中の不透明度から続く、動作低減時はフレームを要求しない。
- 表示設定と右クリックメニュー：閉じた直後のフォーカス復帰、残像の並べ替えボタンが効かない、メニューの残像が閉じた時点のコマンド数を保つ、収束後に外れる。
- 従来からのキー操作、カテゴリ内変更、動作低減時のノブ配置とフレーム要求ゼロ、セグメントの最終配置、バネの収束。

実画面での時間精度・連打中の中間フレーム・OS動作低減の切替、残像の見た目は別途確認が必要。

## 次の段階（未実装）

1. タブの並べ替え：掴んだタブがポインターに追従し、隣がバネで道を空ける。
2. ドラッグ＆ドロップ：持ち上げた項目の影、ドロップ先への着地、失敗時に元へ戻る動き。
3. 一覧の差分：作成・削除・名前変更された行だけを短く動かす。件数に上限を設け、多ければ即時。
4. クイックプレビュー：サムネイルの位置から広がって開く。別ウィンドウのため難度が高い。
5. 拡大縮小：GPUIの `Div` には変形がない。描画層で可能かの調査が必要。
